Two rules that shape every term below

Rule 1 — six of these compounds must never be searched by their bare acronym critical

DOI, MDA, DOM, DPT, MDE and STP are all common abbreviations in biomedical literature for something else entirely: digital object identifier, malondialdehyde, document object model, diphtheria–pertussis–tetanus, major depressive episode, standard temperature and pressure. Searched bare, they return tens of thousands of irrelevant records. The counts below are PubMed, English-language, non-animal — and the last column is the share that has anything to do with psychedelics.

So for those six, the plan uses controlled vocabulary plus the spelled-out chemical name only. This is the same failure mode as the MDMT token being removed below — an acronym that looks like a drug name but mostly matches something else.

Rule 2 — these additions buy precision and auditability, not a flood of new records

Most of these compounds are already being caught by the class-net terms (psychedelic*, hallucinogen*, Hallucinogens MeSH and Pharmacological Action). Estimating in PubMed against a compact RCT proxy, the genuinely new records — those the current strategy would miss — come to roughly 15–20 in total: MDE/MDEA ~10, salvinorin A ~4, and one each for 2C-B, DOET and MDA. The rest add nothing PubMed isn't already returning.

That is an argument for making them explicit rather than against it — a named term is auditable, reproducible, and survives a record that happens to lack the class tag — but the team should not expect a large batch of new screening work. Expect tens, not hundreds.

How to be sure a term is actually working do this before OR-ing anything in

A term inside a 90-term OR chain is invisible. If it is misspelled, uses a thesaurus heading that does not exist, or carries the wrong field tag, it contributes zero and the combined count looks completely normal. You cannot tell a broken term from an absent literature once it is in the chain. Four checks, in order:

  1. Run every new term on its own first

    One term, one count, before it joins the block. Record the number. This is the only point at which a silent failure is visible.

  2. Use the free-text twin as a positive control

    Every vocabulary term in this plan is paired with a free-text form of the same compound. If the free text returns records and the vocabulary term returns 0, the vocabulary term is wrong — a bad heading, a wrong tag, a typo. If both return 0, the compound genuinely is not in that database and the terms are fine. That contrast is what separates the two cases.

  3. Known-item test — the strongest check

    Find one paper you already know is about the compound, then confirm the search returns it. This tests the whole chain end to end, not just that the syntax parses. For group B: a bufotenin pharmacology paper, a 5-MeO-DiPT case report, a Salvia divinorum human study.

  4. Sample the results for relevance

    A term returning far more than expected is usually colliding with something — the lesson of MDA (71,549 records, 0.4% relevant). Read a handful of titles before trusting a large number.

G · Code-name tokenisation fix

existing termsDONE — all 5 databases

This one is not about which drugs are searched but about how the code names are written, and it affects terms already in the strategy. It was found while checking why SPL-026 behaved oddly.

The mechanism: PubMed reads a hyphen as a space

"SPL-026" and "SPL 026" return identical result sets — same counts, same PMIDs. PubMed splits the hyphen into two tokens, spl and 026, and a quoted phrase requires them adjacent and in order. Three spellings therefore behave as three different searches:

Query formMatches a paper writing…Collision surface
"SPL-026"[tiab]SPL-026 or SPL 026low — adjacency required
"SPL026"[tiab]SPL026 only (one fused token)none — a unique token
"SPL-026"[tiab:~3]any spl within 3 words of any 026high — see below

A hyphen and a space are the same search — verified on three platforms

The separated form can be written either way with no effect. PubMed: "bol-148" = "bol 148" = 28 (also confirmed on BPL-003 and HLP-003). Scopus: both spellings return 59. Web of Science: both return 51. Every platform tested treats the hyphen as a token separator, exactly like a space.

So the real distinction is separated vs fused, not hyphen vs space — and four terms written with a space rather than a hyphen (bol 148, BETR 001, NYPRG 101, TD 0148A) are already searching the canonical hyphenated spelling. They need no third form. The concatenated variant is the one that must be added, because a fused token is genuinely unreachable from either separated spelling.

Why :~3 is actively harmful on numeric code names

The token 026 is not unique to code names — it is also how 0.026 indexes. PubMed holds 57,209 abstracts containing the token 026 and 1,548,628 containing 001. So a proximity search for MSD near 001 matches any abstract that defines “MSD” as something (male sexual dysfunction, Modified Sishen Decoction…) and reports p < 0.001 within three words. 33 of MSD-001's 39 proximity hits (85%) contain 0.001.

The HLP-003 case is the important one. Its proximity form returns 3 records, none relevant, and the one genuine record — indexed as HLP003 — is not among them. The two result sets are entirely disjoint. So :~3 is not merely imprecise here; it returns noise and misses the real hit.

What the concatenated form recovers

"SPL026"[tiab] returns exactly three records, and they are the right ones — the Phase IIa DMT trial, the healthy-volunteer safety study, and the DMT pharmacokinetics paper. The literature writes this compound SPL026, so the hyphenated form finds none of them. No hyphenated code name anywhere in the five strategies currently has a concatenated variant.

Proposed rule

Every hyphenated code name gets BOTH forms:      "XXX-000"  OR  "XXX000"

Drop :~3 wherever the prefix is a common abbreviation or the numeric
half could read as a decimal — replace it with the two forms above.
Retain :~3 only for distinctive multi-letter prefixes (NYPRG, GMX, SYNP).

Hyphenated + concatenated covers all three spellings (XXX-000, XXX 000, XXX000) while requiring adjacency, so it is strictly better than :~3 on these terms: same or better recall, and none of the p-value noise. Applying it removes roughly 164 irrelevant records from the PubMed search and recovers real records currently missed.

Standing process — quarterly pipeline surveillance

Psychedelic Alpha publishes its Drug Development Tracker bullseye charts quarterly. Each release is reviewed for compounds newly at phase 1 or later, and any new code names are added to all five strategies. Each new code name is checked on two axes before adding: development phase (phase 1 or later) and mechanism (is the compound actually a psychedelic by this review’s definition?) — CMND-100 passed the first and failed the second. What phase 2 actually did in PubMed verified

Group G removed 18 records from the final PubMed search and added none. All 18 were verified irrelevant — dental implant placement, hepatocellular carcinoma, HIV antiretroviral therapy, acute pancreatitis, plantar-ulcer footwear, cardiology. No psychedelic record was lost.

Note the two different figures: the fix removes 134 records from the drug clause but only 18 from the final set, because the RCT, language, animal and review filters were already absorbing most of that noise downstream. Quote whichever matches the claim being made — the drug-clause figure describes the term fix, the final figure describes the effect on screening load.

Scopus was spot-checked too — its −45 was the largest drop of the five, and all 45 dropped records were confirmed irrelevant. Across the two databases where the dropped set was inspected directly, 63 of 63 removed records were noise and none was a psychedelic study.

Rules that keep the attribution valid

  1. Change nothing else between phases

    No edits to the RCT filter, language limit, or animal/review exclusion blocks. The moment two things move at once, the attribution the phasing buys is gone.

  2. Close the open scope decisions before phase 3 starts

    Groups A–F still contain unratified calls — the salvinorin A mechanism question and the four Embase removals. Settle them first or phase 3 gets re-run.

  3. Update prisma_manual.json at each phase

    Every hand-entered figure changes on a re-run, and build_prisma() raises a warning plus an amber dashboard box when the numbers fail to reconcile. That guard is useful here, but it means budgeting the dashboard update into each phase rather than deferring all three.

  4. Date-stamp a folder per phase

    Export into its own MASTER_DATABASE/search/MM-DD-YY folder each time, following the per-database export instructions in the strategy files. The v1/v2 split already in strategies/ gives the string versions a home; the export folders give the results one.

  5. If three export cycles is too much, attribution only needs counts

    You can run all three string versions in each interface, record the counts, and export just once at the end — full attribution trail, a third of the export work. The tradeoff is losing the phased screening batches, which are worth keeping if reviewers should start on the three-month backlog while the phase 3 decisions are still being argued.

PsycINFO's coverage of these compounds is thin — which is why most of its cells are zero — but its one real hit came via the concatenated form, matching the rest.

    Scopus is the counterexample that justifies keeping both forms

    Until Scopus, the concatenated form won every comparison and the hyphenated form looked redundant — in Embase it was provably a subset. Scopus reverses that for one compound. VLS-01 is found only by the hyphenated form (2 records, 1 relevant); VLS01 returns nothing at all. Yet in the same database SPL026 and HLP003 are found only by the concatenated form, with the hyphenated form returning zero.

    So in Scopus neither spelling dominates — each finds real records the other misses. This is the empirical case for the two-form rule rather than picking a winner, and it retrospectively justifies keeping the hyphenated form in Embase and PsycINFO even where it looked redundant.

    One Scopus-specific detail: quoting changed nothing. TITLE-ABS(SPL026) and TITLE-ABS("SPL026") returned identical results, as did the hyphenated pair. Quote or don't, but stay consistent with the file's existing style.

    Embase differs from PubMed in one instructive way. Its concatenated query form is a superset: searching 'vls01' finds a record whose abstract writes “VLS-01”, but searching 'spl-026' returns nothing when the text writes “SPL026”. So in Embase the concatenated form alone would suffice — the hyphenated form is a subset of it. Keeping both is still the safer default (it costs nothing, and this rests on three probes), but the concatenated form is the one doing the work in both databases.

    Also worth noting: Embase returns 9 relevant records for spl026 against PubMed's 3 — better coverage of this compound, probably conference abstracts. That is 9 records the current Embase strategy cannot reach at all, since it has no SPL-026 term and uses NEAR/4 for every other code name.

    All five databases probed — the rule holds everywhere complete

    Web of Science reproduces Scopus exactly. SPL026 (4 records) and HLP003 (1) are found only by the concatenated form; VLS-01 only by the hyphenated one. Two independent platforms now show the same split, so the two-form rule rests on more than a single observation.

    Proximity earned its keep nowhere. Across all five databases it returned either nothing or noise — in WoS, SPL NEAR/4 026 and HLP NEAR/4 003 returned 0, and VLS NEAR/4 01 returned 9 records of which 8 were irrelevant and the 1 relevant hit was already found by the hyphenated form. No proximity search anywhere found a record the two plain forms missed.

    Quoting was irrelevant in every platform that was tested for it — PubMed, Scopus and Web of Science all returned identical results quoted and unquoted. Keep each file's existing style.

    The probe, for reference — run in each database using a code name with known real records:

    1.  "SPL-026"     (hyphenated)
2.  "SPL026"      (concatenated)
3.  SPL NEAR/3 026   /  SPL W/3 026     (platform proximity form)

Repeat with "BPL-003" / "BPL003", which has 6 known PubMed records.

    How to read the result:

    • 1 and 2 return the same records → that platform normalises hyphens; one form is enough, and group G does not apply there.
    • 1 and 2 differ → same behaviour as PubMed; apply the two-form rule in that database.
    • 3 returns far more than 1 or 2 → proximity is importing noise; sample a few records and check for decimals/p-values before keeping it.

    Record the three counts per database so the decision is documented rather than assumed — the two-form pattern is harmless everywhere, so the safe default if a probe is inconclusive is to include both spellings.
