Read first

Two rules that shape every term below

Rule 1 — six of these compounds must never be searched by their bare acronym critical

DOI, MDA, DOM, DPT, MDE and STP are all common abbreviations in biomedical literature for something else entirely: digital object identifier, malondialdehyde, document object model, diphtheria–pertussis–tetanus, major depressive episode, standard temperature and pressure. Searched bare, they return tens of thousands of irrelevant records. The counts below are PubMed, English-language, non-animal — and the last column is the share that has anything to do with psychedelics.

So for those six, the plan uses controlled vocabulary plus the spelled-out chemical name only. This is the same failure mode as the MDMT token being removed below — an acronym that looks like a drug name but mostly matches something else.

Rule 2 — these additions buy precision and auditability, not a flood of new records

Most of these compounds are already being caught by the class-net terms (psychedelic*, hallucinogen*, Hallucinogens MeSH and Pharmacological Action). Estimating in PubMed against a compact RCT proxy, the genuinely new records — those the current strategy would miss — come to roughly 15–20 in total: MDE/MDEA ~10, salvinorin A ~4, and one each for 2C-B, DOET and MDA. The rest add nothing PubMed isn't already returning.

That is an argument for making them explicit rather than against it — a named term is auditable, reproducible, and survives a record that happens to lack the class tag — but the team should not expect a large batch of new screening work. Expect tens, not hundreds.

G · Code-name tokenisation fix

existing terms · PubMed confirmeddefect

This one is not about which drugs are searched but about how the code names are written, and it affects terms already in the strategy. It was found while checking why SPL-026 behaved oddly.

The mechanism: PubMed reads a hyphen as a space

"SPL-026" and "SPL 026" return identical result sets — same counts, same PMIDs. PubMed splits the hyphen into two tokens, spl and 026, and a quoted phrase requires them adjacent and in order. Three spellings therefore behave as three different searches:

Query formMatches a paper writing…Collision surface
"SPL-026"[tiab]SPL-026 or SPL 026low — adjacency required
"SPL026"[tiab]SPL026 only (one fused token)none — a unique token
"SPL-026"[tiab:~3]any spl within 3 words of any 026high — see below

Why :~3 is actively harmful on numeric code names

The token 026 is not unique to code names — it is also how 0.026 indexes. PubMed holds 57,209 abstracts containing the token 026 and 1,548,628 containing 001. So a proximity search for MSD near 001 matches any abstract that defines “MSD” as something (male sexual dysfunction, Modified Sishen Decoction…) and reports p < 0.001 within three words. 33 of MSD-001's 39 proximity hits (85%) contain 0.001.

Auditing every :~3 code name in the current PubMed strategy against a psychedelic relevance net:

Term as writtenRecordsRelevantEffect
"APEX-90"[tiab:~3]580all noise
"MSD-001"[tiab:~3]390all noise
"APEX-52"[tiab:~3]330all noise
"SON-001"[tiab:~3]190all noise
"AP-188"[tiab:~3]150all noise
"HLP-003"[tiab:~3]30all noise — and misses the 1 real record

The HLP-003 case is the important one. Its proximity form returns 3 records, none relevant, and the one genuine record — indexed as HLP003 — is not among them. The two result sets are entirely disjoint. So :~3 is not merely imprecise here; it returns noise and misses the real hit.

What the concatenated form recovers

"SPL026"[tiab] returns exactly three records, and they are the right ones — the Phase IIa DMT trial, the healthy-volunteer safety study, and the DMT pharmacokinetics paper. The literature writes this compound SPL026, so the hyphenated form finds none of them. No hyphenated code name anywhere in the five strategies currently has a concatenated variant.

Proposed rule

Every hyphenated code name gets BOTH forms:      "XXX-000"  OR  "XXX000"

Drop :~3 wherever the prefix is a common abbreviation or the numeric
half could read as a decimal — replace it with the two forms above.
Retain :~3 only for distinctive multi-letter prefixes (NYPRG, GMX, SYNP).

Hyphenated + concatenated covers all three spellings (XXX-000, XXX 000, XXX000) while requiring adjacency, so it is strictly better than :~3 on these terms: same or better recall, and none of the p-value noise. Applying it removes roughly 164 irrelevant records from the PubMed search and recovers real records currently missed.

Terms to revise in the current PubMed strategy: add concatenated variants to BPL-002, BPL-003, DLX-001, GM-2505, TSND-201, LSR-1019, MSD-001, EMP-01, VLS-01; and replace :~3 with the two-form pattern on AP-188, APEX-52, APEX-90, SON-001, MSD-001, HLP-003, HLP-004, EB-003, MLS-101, PSX-001, NBX-100, NBX-200.

Part 3

Before you run it

Three things need checking in the database interfaces, and the re-run has an order worth following so the PRISMA numbers stay reconcilable.

  1. Confirm the EMTREE terms resolve

    Eight /exp terms in the Embase block are expected preferred terms that could not be verified programmatically. Look each up in EMTREE; if one does not exist, drop that line — the paired :ti,ab free text covers the compound either way.

  2. Check the PsycINFO “Hallucinogenic Drugs” thesaurus term

    Optional but potentially valuable, since it is a class-level term the strategy currently lacks. Verify in the thesaurus browser before adding; if added, note it in the strategy file as a deliberate scope expansion rather than a term-level edit.

  3. Run the tokenisation probe in each of the other four databases required

    Group G is proven for PubMed only. Hyphen handling is a property of each search platform, not of the query — Embase, Scopus, Web of Science and PsycINFO each run different engines, and any of them may normalise hyphens (making the two forms equivalent), treat them as literal characters, or split them as PubMed does. None of this could be tested from outside, since all four are subscription platforms with no open API. Someone logged in needs to run this three-line probe in each, using a code name with known real records: 

    1.  "SPL-026"     (hyphenated)
2.  "SPL026"      (concatenated)
3.  SPL NEAR/3 026   /  SPL W/3 026     (platform proximity form)

Repeat with "BPL-003" / "BPL003", which has 6 known PubMed records.

    How to read the result:

    • 1 and 2 return the same records → that platform normalises hyphens; one form is enough, and group G does not apply there.
    • 1 and 2 differ → same behaviour as PubMed; apply the two-form rule in that database.
    • 3 returns far more than 1 or 2 → proximity is importing noise; sample a few records and check for decimals/p-values before keeping it.

    Record the three counts per database so the decision is documented rather than assumed — the two-form pattern is harmless everywhere, so the safe default if a probe is inconclusive is to include both spellings.

  4. Record the before/after counts per database

    Current totals are PubMed 4,399 · Embase 4,042 · Scopus 2,964 · Web of Science 2,919 · PsycINFO 1,558. Capture the new totals so the PRISMA records identified figure and prisma_manual.json can be updated together. Expect a small net increase — tens of records, not hundreds — and a small decrease in Embase from the four dropped terms.

  5. Re-run all five in one sitting, then re-export

    Mixed-date exports make the deduplication and the PRISMA funnel hard to reconcile. Run and export all five with the same date stamp into a new MASTER_DATABASE/search/MM-DD-YY folder, following the per-database export instructions already in each strategy file.

  6. Expect the new records to be mostly already-screened duplicates

    Because the class-net terms were already catching most of these compounds, a large share of what comes back will deduplicate against records Covidence has already seen. The genuinely new items should be a manageable batch — and worth checking that MDE/MDEA and salvinorin A, the two with the highest marginal yield, behave as expected.

  7. Consider whether other code names have the same alias drift

    Group D was found by asking whether every compound is searchable by every name it has carried. Two further candidates are worth a look on the same principle: HLP005 / CYB005 (a phenethylamine derivative, currently preclinical and in neither strategy), and any future rebrand — the review has already absorbed two company renames (MindMed→Definium, Cybin→Helus).

  8. Update the strategy files and the inventory together

    Once approved, the five files in MASTER_DATABASE/search/strategies/ need editing, and the Drug search inventory needs the new compounds added and the resolved decisions marked, so the two documents do not drift apart.

Not included in this plan

The screening-list candidates ruled out of scope were: TFMPP, BZP and mCPP (piperazines — not 5-HT2A psychedelics; mCPP in particular is a widely used challenge agent that would flood the search), PCP and NR2B NAMs (dissociative / glutamatergic — the review does not search ketamine or any dissociative), α-PVP and 4-fluoroamphetamine (stimulants), mephedrone/4-MMC and 3-MMC (cathinone stimulants — methylone is included because it is the β-keto analog of MDMA, which these are not), GHB (depressant), and calea (oneirogen, not a 5-HT2A psychedelic). Also excluded: m-DASC, which is not a drug at all but the micro-Dimensional Altered States of Consciousness questionnaire — an outcome instrument that had slipped onto the drug list.
